# L08：二维数组、查找与选择排序

每个 `.c` 文件都是一个独立程序，单独编译。不要把多个含 `main` 的文件一起链接。示例使用标准 C17。课堂主线仍使用固定容量数组和小范围 `int` 下标；动态数组是独立的课后选读，先解释必要的指针概念，也可学完L09后阅读。

## 编译与运行

在本目录运行，例如：

```sh
gcc -std=c17 -Wall -Wextra -Wpedantic table_report.c -o table_report
./table_report
```

使用Clang时，将编译命令开头的 `gcc` 换成可用的 `clang`。程序中的短英文输出直接对应变量含义：`row`为行下标，`col`为列下标，`sum`为总和，`mean`为平均值，`max`为最大值，`first/last`为首次/末次位置，`matches`为全部匹配位置，`count`为个数，`rank`为名次。

`linear_search.c`、`selection_sort.c`、`dynamic_batch.c`和`dynamic_append.c`需要输入。其他完整程序直接运行即可。配套的 [outputs](outputs) 保存运行输出，可用于对照自己手算和运行的结果。

## 查找与排序程序的输入约定

- 第一项是数据个数 `n`，范围0～8，十进制文本至多2个字符，包含可能的正负号。
- 接下来输入 `n` 个整数，每项范围−100～100，文本至多4个字符，包含可能的正负号；各项用空白分开。
- 查找程序最后再输入一个目标整数，范围和文本长度与读数相同。`n=0` 时仍需输入目标值。
- 输入转换失败或数值超范围时，程序显示 `ERROR` 并以状态1结束，不输出部分结果。正常完成时返回0。

程序用 `%2d`、`%4d` 限制**每一次**转换的字符数，并检查转换是否成功。这还不是完整数字文本或整行检查：最后一个数字后的多余文字可能留在输入中；一个超长文本也可能被后续转换分成几项。本课按上述受控输入约定使用，后续字符串课再讨论完整文本解析。

例如，排序程序输入 `2 000050` 实际会读成两项0和50；这说明宽度限制不能代替完整文本检查。不要把这种协议外现象当作推荐输入方式。

## 查找示例

编译 `linear_search.c`，输入：

```text
6
52 47 50 47 54 49
47
```

输出为：

```text
first=1 value=47
last=3
matches: 1 3 count=2
```

下标从0开始。首次查找找到后结束循环；末次查找继续向后扫描；全部位置既要输出也要计数。`-1`表示没有找到，不能用作数组下标。位置0是真实位置，不能用 `if (first)` 判断是否找到。

## 排序示例

编译 `selection_sort.c`，输入：

```text
6
52 47 50 47 54 49
```

每轮从尚未就位的区间寻找最小值的位置，再把它与该区间的第一项交换。第一轮结束为 `47 52 50 47 54 49`；最终为 `47 47 49 50 52 54`。完整过程见 [实际输出](outputs/selection_sort__classroom.txt)。

本程序按非降序排列，相邻元素可以相等。`n=0`或`n=1`时无需进行任何一轮选择；数组本身仍然有8格容量。`min_index`每轮重新设为 `i`，扫描从 `i+1`开始。只有两个位置不同才交换，交换前先用临时变量保存旧值。

`selection_cost.c`对相同6项数据作15次值比较和5次非自交换。这里统计的是 `a[j] < a[min_index]` 的求值次数，不包括循环条件等其他比较。对这种写法，`n≥1`时值比较次数为 `n(n−1)/2`；非自交换最多 `n−1`次。`n=0`时两者都为0。已排序的数据仍要完成这些值比较，但可以没有非自交换；不能由此把比较次数等同于实际耗时。

检查排序结果时，既要检查顺序，也要确认每个数出现的次数没有变化。只检查总和、个数、最小值和最大值仍不充分：`1 1 4 4`和`1 2 3 4`具有相同的四项摘要，却不是同一组元素。

## 二维表与原编号

`table_report.c`的行下标表示实验组，列下标表示本组第几次测量，单位为mm，数据为课堂虚构数据。每行4项，行总和为198、200、200；每列3项，列总和为148、156、143、151。

每一行重新从首项建立最大值。严格大于才更新，因此同一行有重复最大值时保留第一次出现的列下标。查找50的首次位置是 `(0,3)`，全部位置是 `(0,3)`、`(1,1)`、`(1,2)`。首次二维查找中，`break`只退出内层循环；外层条件中的 `row == -1`负责在已找到后停止继续扫描。

48～52之外仅按本例规则标为待复查；这些项仍保留在表内并参加统计。此规则不表示真实设备的质量标准。

普通二维数组是“行数组组成的数组”，每一维的下标都必须合法。对 `int table[3][4]`，行下标为0～2，列下标为0～3。不能用 `table[0][4]`代替 `table[1][0]`。

`index_sort.c`排序的是 `order`中的原下标，`reading`不被修改。同值时继续比较原下标，可明确保留原记录的先后。输出原下标依次为1、3、0、2；相应读数为48、50、54、54。这是明确添加第二排序条件，不是说交换式选择排序天然稳定。

`range_rank.c`把极差定义为“本行最大值−最小值”。三行的极差分别为5、2、8，升序排列后的原行下标为1、0、2。同极差时按原行下标排列。排序编号后，原表的组别和测量顺序保持不变。

## 动态数组选读

按`pointer_preview.c → dynamic_batch.c → dynamic_counts.c → dynamic_append.c`阅读。指针保存地址；动态空间中的元素仍可用`a[i]`访问，但数量与容量要由程序另外记录。`sizeof a`只得到指针变量的大小，不能恢复所申请的容量。

两个动态输入程序先读0～12的数量，再读相应项数的−100～100整数。数量文本至多2字符、读数文本至多4字符，均含符号并以空白分隔；前述`scanf`宽度限制的局限同样适用。输出`invalid count`表示数量无效，`invalid reading`表示读数无效，`allocation failed`表示分配失败，`size too large`表示大小超出可表示范围；这些路径以状态1结束，正常完成返回0。输入失败时不显示部分统计或部分数据列表；追加程序此前已经打印的容量变化行可能仍可见。

`dynamic_batch.c`输入`3 49 52 47`，得到[count=3、sum=148、average=49.33](outputs/dynamic_batch__three.txt)。0项单独报告没有平均值，不申请零字节空间、不除以0。最多12个−100～100的读数，任何部分和都在−1200～1200内；若扩大数据规模，应重新检查累加器范围。

`dynamic_counts.c`把49、52、47、50、54、48分为低于48、48～52（含端点）、高于52三类，得到[1、4、1](outputs/dynamic_counts__fixed.txt)。calloc将所有位清零，对本例的int计数器即为0；不能推广成任意浮点或指针类型都获得对应的零值。

`dynamic_append.c`输入`5 49 52 47 50 54`，容量依次为2、4、8，最终[保存5项，容量8](outputs/dynamic_append__five.txt)。每次都先确认`n<capacity`，再写`a[n]`，最后增加n；额外容量尚未写入，不参与输出。已知最终数量时，一次申请通常更直接；这个程序专门演示逐项追加与扩容。

申请字节数之前检查乘法上限，容量加倍之前也检查上限。正大小realloc失败时旧块仍在；用临时指针接结果，成功后才更新a和capacity。成功后不再使用旧指针及旧别名，即使存储位置看起来没有改变。malloc和realloc扩展区未初始化，写入后才能读取；free以后不再访问这块空间。给a赋NULL只改变a，不能修复其他别名。本课不用零大小分配，也不对普通数组调用free或realloc。

动态程序以size_t保存数量和容量，printf使用%zu。它是无符号类型；组合原来的排序时，先处理n<2，再计算n−1，不照搬原程序以小范围int为前提的空数据解释。动态数组选读不要求编写通用容器或引入数组形参。
