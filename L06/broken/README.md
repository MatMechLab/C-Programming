# L06 的故意错误示例

这里的5个程序用于理解编译诊断和定位错误。**每次只选择一个文件，只编译，不链接或运行。** 正确的完整程序位于[上一级目录](../README.md)。

| 文件 | 错误原因 | 修改时先看哪里 |
|---|---|---|
| [missing_return.c](missing_return.c) | 非void函数的一条路径没有给出返回值；走到末尾且调用者使用该值时，行为未定义 | 对照所有分支，补上无效温度应返回的结果 |
| [wrong_arity.c](wrong_arity.c) | 原型只接收一个参数，调用却传入两个 | 对照原型检查实参数量与含义 |
| [out_of_scope.c](out_of_scope.c) | 在内层块结束后使用只在该块声明的valid | 根据结果需要使用的范围安排声明和赋值 |
| [prototype_mismatch.c](prototype_mismatch.c) | 原型声明返回double，定义却写成返回int | 使同一函数的声明与定义具有相容的类型 |
| [void_value.c](void_value.c) | 用void函数的调用结果初始化int变量 | 区分完成一个动作与返回一个数值 |

在课程根目录，例如只检查缺返回的例子：

```bash
gcc -std=c17 -Wall -Wextra -Wpedantic -Werror -c code/L06/broken/missing_return.c -o /tmp/l06_missing_return.o
```

`-c`表示只编译，不生成可运行程序；这条命令预期会报告错误。已安装Clang时，可将`gcc`替换为`clang`观察其诊断。不要添加运行命令。

本课使用`-Werror`，所以缺返回等警告也会使编译失败。不同编译器的英文措辞、行列标记和默认警告级别可能不同；应先读错误所指的源码，再用中文说明原因。不能通过关闭警告来修复函数接口。

缺返回的例子不应运行后猜测“会得到0还是随机数”。它没有可依赖的正常结果；应先根据任务含义补全返回路径，再将修正后的程序作为一个独立文件编译、运行和检查。
