# L03 故意错误示例

这些文件不是正确答案，不应在目录中批量编译并执行。

| 文件 | 问题 | 允许的验证方式 |
|---|---|---|
| [mean_integer.c](mean_integer.c) | 三次读数 10、11、13；先执行整数除法，再转成 `double`，得到 11.000 | 运算有定义；可运行并与正确的 11.333 比较 |
| [parentheses.c](parentheses.c) | 同样的读数，只有第三个读数除以 3.0，得到 25.333 | 运算有定义；可运行并与正确公式比较 |
| [zero_division.c](zero_division.c) | 整数除数为零 | **只编译诊断，禁止执行** |
| [signed_overflow.c](signed_overflow.c) | `INT_MAX + 1` 的有符号结果不可表示 | **只编译诊断，禁止执行** |
| [unsequenced.c](unsequenced.c) | 同一完整表达式中，无先后顺序保证地更新并读取 `count` | **只编译诊断，禁止执行** |

UB 是 undefined behavior（未定义行为）：标准不规定此时程序的行为。不能把一次运行的输出说成规律，也不能把“某个编译器没有给警告”说成没有问题。验证器没有执行后三个文件，包括不在 sanitizer 下执行。

本机 GCC 的整数溢出诊断可能写出 `-2147483648`，Clang 也可能显示相应数值；这只是本机编译器诊断中的计算描述，不能据此教成“有符号溢出总是绕回”。具体原文、版本、命令和退出状态在[本轮代码证据](../../../validation/L03_code_evidence.json)中。
