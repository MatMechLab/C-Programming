# L05 的故意错误示例

这里的程序用于找错，不是参考解答。与正确示例分开编译，保留编译器实际诊断；没有警告也不能说明算法正确。

| 文件 | 错误原因 | 验证方式 |
|---|---|---|
| [off_by_one.c](off_by_one.c) | 从0开始却写 `i <= 6`，会输出7次 | 行为有定义，实际运行对照7行输出 |
| [missing_update.c](missing_update.c) | `i` 一直为0，循环条件无法变假 | 只作编译诊断和状态分析，不运行 |
| [continue_before_update.c](continue_before_update.c) | 到 `i == 2` 后，`continue` 跳过了 `i++` | 只作编译诊断和状态分析，不运行 |
| [zero_extrema.c](zero_extrema.c) | 最小值初始化为0，三个正温度都无法替换它 | 行为有定义，实际得到错误的最低值0，手算应为18 |
| [for_empty_body.c](for_empty_body.c) | `for`后多出的分号成为空循环体，后面的独立块只执行一次 | 行为有定义，实际只打印“第7次记录”，原样保留空循环体或缩进相关警告 |
| [reset_sum.c](reset_sum.c) | 每轮先清零，旧的累计结果被覆盖 | 行为有定义，三轮结束只得到3，题目要求的1+2+3应为6 |

`continue_before_update.c` 的状态可依次分析为 `i=0 → 1 → 2 → 2…`。`while` 中的 `continue` 回到下一次条件判断，不会替你执行循环体后面尚未执行的更新。改用 `for` 也必须确认更新部分确实使循环向终止条件推进。

`for_empty_body.c` 的循环仍会执行初始化、判断和更新，六次执行的是空语句。`i` 从0更新到6后条件为假，随后独立块执行一次，使用 `i + 1` 打印7。该程序不含数组访问，也不发生有符号溢出；错在不符合“输出六条记录”的要求，不是因为空语句本身违反C语法。删除这个例子中多余的分号，才能让后面的块成为循环体。

`reset_sum.c` 的循环次数正确，但总和被反复重置。只删除循环体中的`sum = 0;`，保留循环前的初始化；两种写法都能编译，只有符合累计含义的写法才得到6。`continue_before_update.c`的可运行修复短例见[continue_fixed.c](../continue_fixed.c)，该短例使用编号0～3，强调每条继续路径都能推进。
