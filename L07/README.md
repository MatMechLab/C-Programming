## 编译和运行

在课程根目录编译主程序，再运行：

```bash
gcc -std=c17 -Wall -Wextra -Wpedantic -Werror code/L07/measurement_report.c -o /tmp/l07_report
/tmp/l07_report
```

其他程序采用同样方法，更换源文件名和可执行文件名即可。已安装Clang时，也可把命令中的 `gcc` 改为 `clang`。`-std=c17` 选择C17；三个 `-W...` 选项启用常用警告，`-Werror` 将警告按编译失败处理。

## 输入什么

主程序和偏差程序采用相同输入约定：

1. 先输入0～8之间的十进制整数，表示本批次准备输入的读数个数。这一项最多2个字符，包含可选正负号。
2. 再输入相应个数的整数读数，用空白分隔；每项最多4个字符，包含可选正负号。每个读数须在−100～100之间，包含两端。

课堂的8项数据为：

```text
8
49 52 47 50 54 48 51 53
```

这些是虚构读数。小于48或大于52的已保存读数标为“待复查”；48和52都在本课约定区间内。这个规则用于学习数组，并不代表真实设备的安全或质量标准。待复查的读数仍保存，并参加均值和极值计算。

读入失败、个数超出0～8或读数超出−100～100时，程序输出出错位置并返回1，停止本批次。即使前面已有成功保存的元素，也不会输出这个不完整批次的统计报告。0项输入输出“没有数据”并返回0，不访问 `reading[0]`，也不做除法。

`%2d`、`%4d` 限制的是一次转换使用的字符数，**不会检查完整单词或整行**。例如：

| 输入 | 可能出现的处理结果 |
|---|---|
| 个数为1，最后输入 `49x` | 先转换得到49，尾部的x未被检查 |
| 个数为1，最后输入 `49.5` | 先转换得到49，不能用它输入小数 |
| 个数为2，只输入 `000049` | 两次转换可能分别得到0、49，原来的一个长数字被分开处理 |
| 个数写成 `0008` | `%2d` 先得到0，程序按空数据处理，后面的字符仍未被检查 |

因此应按本课约定输入，不把程序当作通用文本解析工具。只按回车通常还会等待输入，与输入流结束不同。

## 读程序时关注什么

- `reading[8]` 有8个元素，数组下标范围为0～7。`n` 表示已经保存的读数个数；本程序只读取 `reading[0]` 到 `reading[n - 1]`。
- `length_append.c` 中的0也算一项已保存的数据。不能通过数值是否为0判断是否占用；有效长度由 `n` 记录。
- `int partial[4] = {49, 52};` 的后两项会初始化为0。`int reading[8];` 是未初始化的自动局部数组，须先写入相应元素再读取。
- `sizeof reading / sizeof reading[0]` 用于示例中真正的数组对象，得到容量8；它不会自动知道其中已有3项业务数据。后续讲数组用于函数参数时，还需要单独传递长度。
- 主程序先确认 `n > 0`，再用首项初始化极值；全负数据也能处理。比较符号使用严格的 `<` 和 `>`，相等时保留第一次出现的位置。
- 最多8项，每项在−100～100之间，总和在−800～800之间。`(double)sum / n` 先把总和转成浮点数再相除；均值显示为两位小数。
- `practice_deviation.c` 用 `double deviation[8]` 保存 `reading[i] - mean`，并保留 `reading`。偏差有正有负，表示本项相对整批均值的差；它不等于对某个真实值的测量误差。

## 可以自己运行的输入

| 目的 | 输入 |
|---|---|
| 没有数据 | `0` |
| 只有一个读数 | `1`，随后输入 `50` |
| 0也是数据 | `3`，随后输入 `0 49 0` |
| 极值重复 | `4`，随后输入 `54 48 54 48` |
| 全负读数 | `4`，随后输入 `-9 -2 -5 -2` |
| 上下限 | `2`，随后输入 `-100 100` |
| 第二项读取失败 | `3`，随后输入 `49 x 50` |
| 读数超范围 | `1`，随后输入 `101` |

完整8项数据的总和为404，均值为50.50；最小值47在下标2，最大值54在下标4；待复查下标为2、4、7。可以先手算，再观察输出。

[outputs/](outputs/)保存程序的实际标准输出，不包含键盘回显。无输入的程序用 `程序名__fixed.txt`；两个输入程序的8项示例用 `程序名__full.txt`，另外还保存 `empty`、`one_normal`、`all_negative` 等输入结果。`trailing_text`、`split_wide_token` 等文件帮助观察前述输入方式的局限。
